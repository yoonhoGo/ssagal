# "쌰갈!" 플로팅 앱 — 설계 문서

작성일: 2026-06-11

## 개요

Tauri로 만드는 데스크톱 장난감 앱. 화면 위에 항상 떠 있는 작은 말풍선 버튼("쌰갈!")을
누르면 번들된 음원 파일("쌰~갈~!")이 재생된다. **연타하면 이전 소리를 끊지 않고 중첩 재생**되며,
x3/x5/x10 프리셋으로 지정한 횟수만큼 (순차로) 자동 반복할 수 있다.

## 핵심 결정 사항

| 항목 | 결정 |
| --- | --- |
| 앱 형태 | 플로팅 윈도우 (always-on-top, 프레임리스, 투명 배경, 드래그 이동) |
| 음원 소스 | 번들 음원 파일 `src/assets/ssyagal.m4a` (HTMLAudioElement로 재생) |
| 버튼 글자 | `쌰갈!` (이미지 키링 디자인 차용) |
| 연타 동작 | 매 클릭마다 새 `Audio` 인스턴스 생성 → **중첩 재생** (이전 소리 유지) |
| 반복 조작 UI | 프리셋 버튼 `x3` / `x5` / `x10` + `중지` (자동 반복은 클립 종료 후 다음 재생, 순차) |

## 아키텍처

- **Tauri 2.x** 단일 윈도우 앱.
- 프론트엔드는 **순수 HTML/CSS/JS** (프레임워크 없음 — 화면이 단순해 불필요).
- **재생은 프론트엔드 `HTMLAudioElement`로 완결.** 번들 음원(`/assets/ssyagal.m4a`,
  AAC-LC)을 WKWebView가 직접 재생. Rust 백엔드의 오디오/명령 호출 플러그인이 필요 없어
  권한·설정이 단순하다.
- Rust(`src-tauri`)는 윈도우 생성·설정만 담당하고 비즈니스 로직은 두지 않는다.

### 모듈 경계

| 단위 | 책임 | 의존성 |
| --- | --- | --- |
| `index.html` | 말풍선 버튼 + 프리셋 + 중지 버튼 마크업 | `style.css`, `main.js` |
| `style.css` | 말풍선/입체감/프리셋 pill/누름 애니메이션 스타일, 번들 폰트 | 번들 폰트(Jua) |
| `player.js` | 음원 재생 + 자동 반복 상태 머신 (순수 로직, DOM 비의존) | HTMLAudioElement |
| `main.js` | DOM 이벤트를 `player.js`에 연결, 진행 카운트 표시, 윈도우 드래그 | `player.js` |
| `src-tauri/` | 프레임리스·투명·always-on-top 윈도우 설정 | Tauri |

`player.js`는 `makeAudio` 팩토리를 주입받아 DOM에 의존하지 않게 분리해 단위 테스트 대상으로 삼는다.

## 윈도우 설정 (`tauri.conf.json`)

- `decorations: false` (프레임 없음)
- `transparent: true` (말풍선만 둥실 떠 보이게)
- `alwaysOnTop: true`
- `resizable: false`, 고정 크기 약 **240 × 280**
- `skipTaskbar: true` (작업표시줄/Dock 노출 최소화)
- 드래그 이동: 말풍선 영역에 `data-tauri-drag-region` 적용

## UI 구성 (한 화면)

1. **큰 "쌰갈!" 말풍선 버튼** — 누를 때마다 음원 1회 재생.
   연타 시 직전 소리를 끊지 않고 **중첩 재생**(여러 소리가 동시에 겹침).
2. **프리셋 줄**: `x3` `x5` `x10` 둥근 pill 버튼 — 누르면 해당 횟수만큼 순차 자동 반복.
3. **`■ 중지` 버튼** — 자동 반복 중단 + 현재 재생 중인 모든 소리 정지.
4. **진행 카운트** 표시(예: `3 / 5`). 유휴 시 숨김 또는 비표시.

## 버튼 디자인 (이미지 반영)

- **모양**: 흰색 둥근 말풍선(타원형) + 굵은 검정 외곽선(약 6~8px) + 좌하단 꼬리(tail).
  뒤쪽에 검정 받침을 살짝 오프셋해 키링 같은 입체 그림자.
- **글자**: `쌰갈!`을 굵고 둥근 폰트로. 가장 비슷한 무료 폰트는 **Jua**(둥글고 도톰).
  오프라인 동작을 위해 **폰트 파일을 앱에 번들**(웹 폰트 CDN 의존 금지).
  글자에 다중 그림자/스트로크를 주어 키링처럼 **양각 입체감** 연출.
- **누름 피드백**: `:active` 시 살짝 scale down + 그림자 축소로 "꾹" 눌리는 촉감.
- 프리셋·중지 버튼: 말풍선 톤에 맞춘 **검정 테두리 + 흰 배경의 둥근 pill** 스타일로 통일.

## 재생 / 반복 상태 머신 (`player.js`)

`createPlayer({ src, gapMs, makeAudio, setTimeout, onChange })` — `makeAudio`(기본
`(s) => new Audio(s)`)와 타이머를 주입받아 DOM/브라우저 없이 테스트 가능.

상태:

- `isAutoPlaying: boolean`
- `remaining: number` — 남은 자동 반복 횟수
- `total: number` — 진행 표시용

내부적으로 현재 재생 중인 `Audio` 인스턴스를 `active` Set으로 추적한다(중지 시 일괄 정지).

동작:

- `playOnce()` — 다른 소리를 멈추지 않고 **새 `Audio` 인스턴스를 만들어 재생**(중첩).
- `startRepeat(n)` — `total=n`, `remaining=n`로 세팅하고 자동 반복 시작.
  타이머 race를 피하기 위해 한 클립의 `ended` 이벤트가 끝나면 다음 재생을
  트리거하는 **순차 체인 방식**. 재생 간 간격은 짧게(약 300ms).
- `stop()` — `active`의 모든 오디오를 `pause()`+`currentTime=0`으로 정지하고 카운트 리셋.

## 엣지 케이스

- 음원 재생 실패(`error` 이벤트) → 해당 인스턴스를 `active`에서 정리(앱은 계속 동작).
- 자동 반복 중 다른 프리셋 클릭 → `startRepeat`가 카운트를 새로 세팅(기존 체인은 상태 가드로 자연 종료).
- 윈도우 투명/프레임리스에서 드래그 영역과 버튼 클릭 영역 충돌 방지(버튼은 드래그 영역 제외).

## 테스트

- 실제 오디오 출력은 자동화가 어렵다. **순수 상태/재생 로직만 분리해 단위 테스트**:
  - `playOnce()`가 오디오 1개를 만들어 재생하는지, 기본 경로가 `/assets/ssyagal.m4a`인지
  - 연타 시 이전 소리를 멈추지 않고 중첩 재생하는지
  - `startRepeat(n)`이 순차로 정확히 n회 재생하고 종료 상태가 되는지
  - `stop()`이 모든 소리를 멈추고 상태를 리셋하는지
- `Audio`는 테스트에서 **fake 팩토리로 주입**(의존성 주입)하여 생성/재생/정지 호출을 검증.
- 테스트 러너: node test runner.
- 실제 소리 출력·윈도우 표시·디자인은 수동 확인.
